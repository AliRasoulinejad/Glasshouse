Heap page field glossary

Plain definitions for the fields the byte map shows. Each term appears in the page header, in an item pointer, or in a tuple header. Open this page from a field name in the Inspector to go straight to its entry.

Page header

lsn
The LSN identifies the last WAL (write-ahead log) record that changed this page. PostgreSQL uses it to keep the page and the log in step.
checksum
The checksum value protects the page data against storage corruption. It is 0 if the cluster was created without checksums.
flags
The flags show the page status, for example whether the page has free space registered in the free space map, or has a pending full-page image in the WAL.
lower
The lower value is a byte offset. It marks where the item pointer list ends and the free space region starts.
upper
The upper value is a byte offset. It marks where the free space region ends and tuple data starts. PostgreSQL packs tuples from the end of the page toward the start.
special
The special value is a byte offset. It marks the start of the special area at the end of the page. A heap page has no special area, so this value equals the page size.
page_size
The page size is the total size of the page in bytes. PostgreSQL uses 8192 bytes by default.
version
The version number identifies the layout format of the page.
prune_xid
The prune_xid value is the oldest transaction ID that may still need pruning on this page. PostgreSQL uses it to decide when HOT pruning can run.
free_space
The free_space value is the number of bytes open between lower and upper, for new item pointers and new tuple data.

Item pointer

lp
The lp value is the position of this pointer in the item pointer list. The list starts at 1. The block number and the lp value together identify one row; this pair is the row's ctid.
lp_off
The lp_off value is the byte offset within the page where this tuple's data starts.
lp_len
The lp_len value is the length of the stored tuple in bytes. It is 0 if the pointer is not in use.
lp_flags
The lp_flags value shows the state of the pointer. 0 means the pointer is not in use. 1 means normal: the pointer leads to a live tuple. 2 means redirect: the pointer leads to a newer pointer, set after a HOT update. 3 means dead: the tuple is gone and waits for VACUUM to reclaim the pointer.

Tuple header

t_xmin
The t_xmin value is the ID of the transaction that added this tuple. A later transaction can see this tuple once the t_xmin transaction has committed.
t_xmax
The t_xmax value is the ID of the transaction that removed or changed this tuple. A value of 0 means no transaction has done so; the tuple is still live.
t_ctid
The t_ctid value points to the current version of this tuple. It points to itself if this row is live. It points to a newer tuple's block and lp if an UPDATE replaced this row.
t_infomask
The t_infomask value is a set of flag bits about the tuple, for example whether t_xmin and t_xmax are known to be committed, and whether any column holds a null value.
t_infomask2
The t_infomask2 value is a second set of flag bits. Its low bits also store the number of columns in the tuple.
t_hoff
The t_hoff value is the length of the tuple header in bytes. Column data starts right after this offset.
t_bits
The t_bits value is the null bitmap, one bit per column, marking which columns are null. "(none)" means no column is null, so PostgreSQL left the bitmap out.
t_data_hex
The t_data_hex value shows the raw bytes of the tuple's column data, after the header, in hexadecimal format.
id
The id value is the real, decoded value of the row's id column, read live from the table by its ctid. "(none)" means no live row exists at this location right now — this line pointer is dead or unused.
payload
The payload value is the real, decoded value of the row's payload column, read live from the table by its ctid. "(none)" means no live row exists at this location right now — this line pointer is dead or unused.
